# Container Loading Simulator

화물·완성 팔레트를 A 적재 모듈로 배치하고, 3D 결과·위반 내용·작업지시서·Excel을 확인하는 웹 앱입니다.

## 현재 적재 방식

2026-10-04 사용자 지시에 따라 `load-sim-all-in-one(3).md`의 A 방식으로 전환했습니다.

- 자동 배치: A `pack`
- 수동·그룹 이동 후보: A `canPlace`
- 최종 판정: A `validate`
- 박스·팔레트·혼합 모드의 컨테이너 배치는 모두 같은 A 경로 사용
- 기존 Hybrid/StrictWall/컨테이너 Beam, B 후처리·재배치, 선택 플래그 제거
- 기존 capacity/stability/unloading 호출 인자는 이전 호출부 호환용이며 다른 컨테이너 알고리즘을 선택하지 않음

A는 무게·부피·바닥면적 순서 및 결정론적 교란 순서를 시도합니다. 카톤의 기본 허용 방향은 A의 6방향이며, 천지무용·명시적 허용 방향·회전 금지 입력을 적용합니다.

`canPlace`는 모든 최종 규칙을 검사하지 않습니다. `pack`이 좌표를 반환했더라도 최종 혼적·무게중심·축하중 등의 오류가 있을 수 있습니다. 앱은 최종 오류를 유지하고, 그런 결과에 A 정적 검증 통과를 부여하지 않습니다.

## 판정 의미와 데이터 출처

화면·작업지시서의 **A 정적 규칙 검증**은 입력 모델에 대한 정적 판정입니다. 실제 운송 안전 인증이나 법규·제조사 제원 확인을 뜻하지 않습니다.

A 기본 설정과 제공 장비 프리셋은 대표값입니다. 실제 장비·화물 제원으로 확인해야 합니다. 가상 트럭 축 데이터는 자동 적용하지 않습니다. 축 데이터나 바닥 선하중이 없으면 해당 검사가 생략됐음을 표시합니다.

- 앱 치수/좌표: m, kg
- A 경계: mm, kg
- X: 안쪽 벽에서 도어 방향, Y: 폭, Z: 높이
- A 바닥 선하중: kg/m
- 기존 바닥 격자 시각화: kg/m², 선하중 한도와 별개
- 상부 허용중량 누락: 제한 미지정; 0: 상부 적재 금지

Rapier·관성 검사는 별도로 실행할 수 있는 선택 검사입니다. A 정적 성공을 관성 PASS로 만들거나, 선택 관성 결과 때문에 A 배치가 다른 방식으로 자동 재배치되지 않습니다.

## 팔레트 준비와 적재의 구분

A에는 박스를 팔레트에 만드는 기능이 없습니다. 포장·팔레트 데크 준비는 별도 준비 단계로 유지합니다. 데크 전용 기하·지지·포장·결합 규칙은 컨테이너 배치의 대체 경로가 아닙니다.

완성 팔레트는 실제 적재 높이·자중/포장재 포함 총중량·무게중심을 가진 강체로 A에 전달합니다. 혼합 모드는 완성 팔레트와 실제 느슨한 잔량만 함께 전달합니다. 컨테이너 배치 후 B 재정렬·중앙 이동·70% demotion·전략 재시도는 없습니다.

화면의 팔레트 내 박스와 A 강체 입력의 좌표 대응을 보존합니다. 차량 중량은 강체 팔레트와 표시용 자식 박스를 중복 합산하지 않습니다. 하역순서·혼적·온도 속성이 다른 화물은 호환 준비 그룹으로 분리합니다.

## 결과와 복원

A 판정은 현재 장비, 원본 화물, 실제 방향/좌표, 팔레트 강체와 표시 박스의 대응을 포함한 별도 서명으로 관리합니다. 입력 변경이나 오래된 결과 요청은 기존 통과 기록을 재사용할 수 없습니다.

- 적재수와 미적재수는 SKU별로 보존
- 제품 EA와 포장 단위 수 구분
- 빈 결과는 미적재 사유만 제공
- 최종 오류는 숨기지 않고 결과에 표시
- 입력 변경·취소 후 늦게 도착한 계산은 적용하지 않음
- 실제 6방향 코드는 화면과 Excel에 L/W/H 축 순서로 표시

## 주요 코드

- `src/load-sim/`: A 배치·검증·기본 설정
- `src/rule-engine/loadSimAdapter.ts`: 단위·방향·개별 ID 변환
- `src/rule-engine/loadSimEngine.ts`: 입력 무결성과 A 호출
- `src/rule-engine/acceptance.ts`: 정확한 현재 결과의 A 정적 판정
- `src/engine/loadingEngine.ts`: 앱 공용 A 진입점
- `src/engine/palletContainerPlacement.ts`: 준비된 팔레트 강체의 A 배치
- `src/engine/palletPacking.ts`, `palletOptimization.ts`: 별도 팔레트 준비

## 개발과 검증

Node/npm 의존성을 설치한 뒤 실행합니다.

```sh
npm run dev
npm run test
npm run typecheck
npm run check:architecture
npm run build
npm run check:bundle
npm run verify:predeploy
npm run test:e2e
```

테스트는 A 원본 규칙, 동일 입력 결정론, 수량, 6방향/CG 변환, 잘못된 입력, 최종 오류, 수동 이동, 팔레트 강체, 오래된 판정 차단 및 출력 경로를 다룹니다.

브라우저 검증은 실제 Chromium 실행이 필요합니다. 실행 환경이 브라우저 소켓/로컬 주소 접근을 제한하면 UI 단위 테스트와 브라우저 E2E 실행 여부를 구분해 보고해야 합니다.

# 차량 후방 적재 대기장

등록한 화물을 계산 전부터 차량 후방의 3D 대기장에 실제 외형 규격으로 표시한다.
직접 박스, 파렛트, MIXED 모드에서 현재 차량과 대기 화물을 같은 화면에서 선택하고,
검사를 통과한 화물만 상차하거나 대기장으로 회수할 수 있다. 적재 엔진의 기존
알고리즘·우선순위·안전 한도는 유지한다.

## 수량과 포장 상태

- 전체 준비량, 현재 차량 배치량, 대기량을 파렛트·낱박스·내부 박스 총수량으로
  구분한다. 계산 결과 미적재량은 대기량의 일부이며 두 수량을 더하지 않는다.
- 어댑터에 같은 채택 계획의 다른 차량 배치가 전달된 경우 별도 수량으로 구분한다.
  현재 작업 화면은 선택한 차량을 대상으로 하며, 비교 후보나 오래된 결과를 실제
  출하 수량에서 중복 차감하지 않는다.
- 제품 포장이 확정되기 전에는 제품 EA를 실제 박스 수량으로 취급하지 않는다.
  파렛트 포장은 기존 포장 계산을 재사용하며, 계산 중·실패·제외된 입력과 실제 사유를
  표시한다. 포장이 필요한 미완성 낱박스를 직접 상차해 파렛트 모드를 우회할 수 없다.
- 대기장에 놓인 포장 파렛트는 포장 **계획**이다. 화면에 밴딩·랩핑·각대가 표시되어도
  현장 시공 확인이나 실제 운송 안전 인증을 뜻하지 않는다.

## 표시와 조작

확정 상차 후 실제 화물 인스턴스가 대기장에서 차량으로 이동한다. 연출은 기존 렌더
루프에 연결하며 수량·채택 배치·인증 데이터를 바꾸지 않는다. 건너뛰기와 OS 동작 줄이기를
지원한다. 공개 모듈 API와 기존 앱 연결 범위는 [화물 이동 모듈](CARGO_MOTION.md)에 설명한다.

전체 보기·차량 내부·대기장 보기, 3D 선택과 검색 가능한 목록, 품목·규격·중량·포장·
하역 순서·미적재 사유 상세를 제공한다. 목록은 4개 단위로 이동한다. 대기 화물이
20개 이하면 모든 구역을 표시하고, 더 많으면 한 화면에 최대 4개 구역씩 표시한다.
현재 표시 구역과 전체 구역 수를 함께 보여 주며, 숨겨진 구역의 화물도 전체 수량과
목록에는 포함한다.
검색으로 화면 밖 구역의 화물을 선택해도 카메라를 자동 이동하지 않는다. 선택 상세의
**선택 화물 구역 보기**를 누른 경우에만 해당 구역 페이지를 연다. 이미 표시 중인
구역이나 차량 내부 화물에는 이 버튼을 표시하지 않는다.

대기장 정렬과 카메라·구역 페이지 변경은 표시만 바꾼다. 대기장 좌표와 통로·출입문
여유는 차량 밖의 시각 배치이며 차량 적재 좌표나 현장 동선 검증값으로 사용하지 않는다.

메인 작업 화면의 명시적 시점 전환은 우리 제품의 375ms 보간을 사용한다. 첫 장면 맞춤,
장비 형상 변경, reduced-motion 환경과 진단·재생의 즉시 시점 경로는 즉시 적용한다.
직접 Orbit 조작을 시작하면 진행 중인 보간을 취소하고, 화물 드래그 중에는 카메라
조작을 잠근다. 화물·선택·품질 갱신만으로 사용자가 맞춘 시점을 초기화하지 않는다.

화면 품질과 안전 상태도 분리한다. 렌더 해상도·조명·재질·접촉 음영의 표시는 화물
수량·규격·좌표·포장 구성·중량·미적재 사유를 바꾸는 입력이 아니다. 품질을 바꿔도
재적재·운송 인증을 실행하거나 기존 검증을 무효화·승격하지 않는다. 특히 선명한
접촉 음영이나 실제처럼 보이는 랩핑은 지지 판정·현장 포장 확인·안전 PASS의 근거가 아니다.

### 3D 품질 설정

`3D 품질`과 `접촉 음영`은 현재 브라우저 세션의 표시 설정이다. 기본값은 표준·접촉
음영 켜짐이며, 회원 작업 데이터나 저장된 적재 계획에 섞지 않는다. 브라우저 저장이
차단된 경우 현재 메모리에서 선택을 유지한다. 여러 표시 컨트롤은 같은 세션 설정을 읽는다.

| 설정 프로필 | 화면 DPR 범위 | AO 해상도 배율 | AO 표본 설정 | 후처리 MSAA 상한 | 직접 그림자 맵 |
| --- | --- | --- | --- | --- | --- |
| 고품질 | 1–1.5 | 1 | 16 | 4 | 2048² |
| 표준 | 1–1.25 | 0.5 | 8 | 2 | 1024² |
| 성능 우선 | 1 | 0 / 비활성 | 0 | 0 | 끔 |

실제 DPR은 장치의 픽셀 비율과 프로필 상한에 따라 달라진다. 이 값들은 화면 표시
비용을 제어하는 설정이며 프레임 속도를 보장하지 않는다. 성능 우선에서는 접촉
음영 체크박스를 비활성화하지만, 이전 AO 선택은 다른 품질로 돌아갈 때 사용할 수
있도록 유지한다. 품질 전환은 화물 배치·수량·선택 개체 ID를 재작성하는 경로가 아니다.
후처리 MSAA 표본 수는 장치의 `maxSamples`와 RGBA16F 실제 지원 표본 수를 확인해
프로필 상한 안에서 선택한다. 지원 조합이 없으면 0으로 동작한다. AO가 없는 직접
출력의 기본 Canvas 안티앨리어싱은 별도이며, 표의 0이 모든 경계 처리를 끈다는 뜻은 아니다.

접촉 음영이 켜진 표준·고품질 경로는 기존 장면, GTAO 접촉 음영, 최종 출력 순으로
합성한다. 반투명 랩·라벨·스프라이트와 내부가 잘린 외벽은 원래 화면에는 유지하되
불투명 깊이·노멀로 생성하는 AO 입력에서는 제외한다. 음영 계산 후 가시성을 복구한다.
AO를 끄거나 성능 우선을 선택하면 기존 직접 렌더링을 사용한다. 후처리 생성·실행이
실패하거나 필요한 float framebuffer 확장을 지원하지 않으면 오류를 표시하고 직접
렌더링으로 돌아가며, 적재 결과를 대신 생성하지 않는다.

후처리 버퍼·노이즈·장면 전용 재질은 소유한 표시 계층에서 해제한다. 공유 원본 모델의
geometry와 텍스처 캐시는 품질 전환 때 폐기하지 않는다. 정지 화면은 demand 렌더링을
유지하며, 카메라·애니메이션·명시적 표시 변경 때만 새 화면을 요청한다.

### 박스·포장과 조명 표현

작업 화면의 박스는 실제 외형 경계와 치수를 유지하는 공유 라운드 박스를 사용한다.
단위 박스 모서리 반경은 0.005이며 표시용 형상은 108삼각형이다. 차량 내부·대기장·
드래그 미리보기에서 같은 형상 풀을 사용한다. 이 둥근 표면은 표시 전용이고, 적재와
충돌·지지·중량 검사는 기존 직육면체 규격을 계속 사용한다.

박스 표면은 크라프트 PBR 재질(roughness 0.92, metalness 0, 텍스처 map 없음)에 품목색을
반영한다. 메인 차량 뷰의 제품·SKU 표시는 기존 별도 인쇄 라벨 경로를 사용하고,
대기장에는 구역·선택 화물의 이름·상태 라벨과 상세 목록을 표시한다. 원본 carton JPEG는 원본 OBJ에
맞춘 조각난 UV atlas이므로 라운드 박스 표면에 늘여 붙이지 않는다. 원본 OBJ·JPEG·UV
데이터와 기존 원본 재질 팩토리의 캐시·호환성 검사는 보존하지만, 작업 화면 박스가
원본 OBJ의 UV를 그대로 렌더링한다는 뜻은 아니다. 파렛트·차량·각대 등 다른 모델은
각자의 원본 geometry·텍스처와 PBR 재질을 사용한다.

반구광·주광·보조광과 실내 환경광 반사를 조합하며, 환경광은 현재 장면의 renderer에
한 번 준비해 품질·카메라 변경 때 다시 만들지 않는다. 직접 그림자는 품질 프로필에
따라 조정하고 바닥의 표시 그림자는 실제 외부 바닥 높이를 따른다. 음영·반사는
화물의 실제 접촉이나 차량 내 유효 공간을 계산하는 데이터로 전달하지 않는다.

원본 텍스처가 있는 PBR 재질은 해당 색을 한 번 선형화한다. 절차적 배경색도 후처리의
선형 화면과 직접 출력에서 동일한 출력 변환 경로를 사용해 AO를 켤 때 감마 보정이
중복되지 않게 한다. 정확한 색·투명 랩·라벨의 표현은 실제 WebGL 화면에서 별도로 확인한다.

대기 화물을 선택해 **선택 화물 적재**를 누르면 기존 공간·스냅 계산과 현재 제약으로
차량 내 유효 위치를 찾는다. 3D 드래그는 현재 위치의 허용 여부와 사유를 미리 보여
주고, 놓는 순간 현재 입력으로 다시 검사한다. 실패하면 기존 배치와 수량을 보존한다.
포장 파렛트는 내부 박스를 함께 이동하며 개별 박스로 분해하지 않는다.

## 안전 검사와 되돌리기

상차·회수는 차량 경계, 충돌, 지지, 회전·적층·상부하중, 파렛트 포장과 전체 중량,
차량 허용 중량·바닥하중·하역 제약 등 기존 검사를 재사용한다. 위 화물을 지지하는
하부 박스·파렛트는 먼저 회수할 수 없으며, 상부 파렛트는 기존 파렛트 적층 조건을
모두 만족해야 한다. 현재 화면의 다른 차량 화물을 회수해 가져오는 기능은 제공하지 않는다.

성공한 변경과 되돌리기는 이전 운송 검증을 무효화한다. 되돌리기는 현재 입력·자재·
제약으로 이전 좌표와 파렛트 포함 관계를 다시 검사하며, 과거 PASS를 복원하지 않는다.
정적·물리 검사와 기존 작업지시서·내보내기 승인 경로는 그대로 유지한다.
WHAT-IF REVIEW의 기존 직접 박스 범위도 확대하지 않는다.

## 저장과 복원

기존 작업 저장 형식에 선택 개체 ID, ID 별칭, 입력 서명, 모드와 파렛트 계획을 선택
메타데이터로 추가한다. 야드 수량과 표시 슬롯은 저장된 별도 재고로 관리하지 않고
현재 입력과 채택된 차량·포장 계획에서 다시 계산한다. 예전 입력 전용 저장은 계속 읽는다.

작업자 범위, 모드, 전략·화물·차량·파렛트 규격을 반영한 입력 서명이 일치할 때만
복원하며, 구조가 손상된 메타데이터는 버린다. 복원할 차량 배치도 현재 안전 검사와
수량·개체 ID·파렛트 포함 관계 검사를 통과해야 한다. 새로운 입력에 옛 작업의
대기장 메타데이터를 상속하지 않는다. 입력이나 채택한 계획이 바뀌면 임시 선택·드래그·
되돌리기 이력을 초기화한다.

영구 보관은 기존 회원 작업 저장 계층을 사용한다. 기존 게스트의 메모리 전용 정책을
유지하므로 새로고침·종료 후 복원을 보장하지 않는다. 대기장은 별도 인증·계정 권한이나
새 클라우드 저장 서비스를 추가하지 않는다.

## 구현 경계와 검증

- `stagingInventory.ts`: 입력·포장·차량 결과에서 수량과 안정적인 개체 ID를 도출한다.
- `stagingYardLayout.ts` / `ThreeStagingYard.tsx`: 차량 뒤 외부 배치와 3D 선택·드래그를 담당한다.
- `engine/stagingCommands.ts`: 상차·회수·복원의 순수 검증·결과를 제공하며 저장·이벤트·인증을 직접 발행하지 않는다.
- `StagingWorkspace.tsx`: 현재 입력, 표시 패널, 기존 결과 채택·인증 무효화·저장·되돌리기를 연결한다.
- `stagingPersistence.ts` / `storage.ts`: 선택 메타데이터의 구조와 입력 일치를 검사하고 구형 저장과 호환한다.
- `useStagingPackaging.ts` / `stagingPackaging.worker.ts`: 포장 계산만 분리하며 취소·늦은 응답·작업자 오류를 처리한다.
- `viewerQuality.ts` / `ViewerQualityControls.tsx`: 세션 표시 설정과 동기화된 품질·접촉 음영 컨트롤을 제공한다.
- `ThreeRenderPipeline.tsx`: 직접 출력과 AO 합성의 단일 렌더링 경로, 해상도 조정·오류 복구·후처리 자원 해제를 담당한다.
- `threeComparisonModels.ts` / `ThreeSceneLighting.tsx`: 작업 화면의 공유 박스 형상·PBR 재질·색공간과 환경광·그림자 자원 수명을 담당한다. 원본 자산 보존과 작업 화면 재질은 구분한다.
- `cameraMotion.ts` / `ThreeComparisonScene.tsx`: 명시적 카메라 전환·사용자 조작 취소·동작 줄이기와 기존 시점 보존을 담당한다. 화물 위치를 보간하는 기능은 아니다.

관련 회귀검사는 수량 보존과 ID, 직접·파렛트·혼합 포장, 외부 배치와 구역, 안전 명령,
저장 호환·손상 데이터, 비동기 작업 취소, 표시 패널과 통합 컨트롤러를 검증한다.
품질 설정 회귀검사는 저장 차단·잘못된 값·컨트롤 동기화·이벤트 해제와 함께 품질
변경이 작업 저장·적재 입력 서명·개체 ID·물리 대상·현재 인증을 바꾸지 않는지 확인한다.
실제 렌더링 성능은 [측정 기록](../performance/STAGING_YARD_RENDERING.md)에 실행 환경,
전체·표시 수량, 해상도·DPR·품질·AO, 캐시와 표본 조건을 함께 기록한다. 소프트웨어
렌더러의 E2E 결과를 하드웨어 GPU 성능이나 적재 계산 속도로 보고하지 않는다.
프로젝트 운영 규칙은 [COLLABORATION](../agents/COLLABORATION.md), 엔진 안전 기준은
[LOADING_RULES](../engine/LOADING_RULES.md)를 따른다.
외부 상호작용 참고의 직접 관찰·미확인 내용과 독립 적용 범위는
[AirSup 관찰 기록](../comparison/AIRSUP_INTERACTION_NOTES.md)에 구분해 기록한다.

# 적재 결과 직접 점검

자동 적재 후 **메뉴 → 점검**의 **경계·충돌 점검**, **무게중심 점검**, **총중량·바닥 하중 추정**, **관성 테스트** 중 하나를 바로 선택합니다. 각 항목이 메뉴에 직접 표시됩니다.
점검은 배치를 바꾸거나 작업지시서를 승인하지 않습니다. 실제 운송 안전 인증이 아닙니다.

| 항목 | 재사용하는 계산 | 범위와 제한 |
| --- | --- | --- |
| 경계·충돌 | `validatePlacements` | 상자와 팔레트 바닥판의 직육면체 경계·겹침. 지지·적층·누적 상부하중은 이 항목에 포함되지 않음 |
| 무게중심 | `assessWeightBalance` | 상자 중량과 팔레트 바닥판 자중을 한 번씩 포함. 좌표·편차만 표시하며 등급을 운송 안전 판정으로 사용하지 않음 |
| 총중량·바닥 하중 추정 | `analyzeFloorLoad` | 적재중량 한계 비교, 12×4 격자 투영 추정. 바닥 기준이 없으면 비교 미실행. 발 접촉압·지지 전달하중·차량 축하중은 계산하지 않음 |
| 관성 테스트 | `runInertiaAnimation` | 현재 적재 결과의 메인 3D 캔버스에서 재생합니다. 출발 0.30g, 급제동 0.50g, 급회전 0.35g 선택 및 재생·일시정지·타임라인·속도 조절. 동일 대상의 기존 결속 결과 또는 기존 엔진 기본 결속 조건 사용 |

팔레트 모드도 `PhysicsTarget`의 상자와 별도 바닥판을 그대로 사용합니다. 원본 좌표, 자동 적재 알고리즘, 모델 자산, 저장 데이터는 바꾸지 않습니다.

경계·충돌, 무게중심, 하중 계산은 Web Worker에서 실행합니다. 관성 애니메이션은 기존 Rapier 프레임 계산과 취소 기능을 재사용합니다. 중복 실행은 막고 **실행 취소** 또는 **관성 계산 취소**, **닫기**, Escape, 브라우저 뒤로 가기 시 실행을 중단하고 늦은 응답을 폐기합니다. 입력·장비·결속 조건·적재 대상이 바뀌면 이전 점검 결과도 폐기합니다. 다시 열 때 과거 `window` 적재 결과를 우회 복구하지 않습니다. 유효한 결과가 없으면 자동 적재를 먼저 실행해야 합니다.

3D는 Three.js만 사용하며 기존 8개 Meshy 모델과 차량 모델을 유지합니다. Unity 런타임과 엔진 선택 UI는 제거되었고, 과거 `?renderer=unity`·`?renderer=compare` 주소도 Three.js를 엽니다. 배경은 작업 화면 상단의 공통 **배경** 선택기로 바꿉니다. 이 화면 설정은 적재 결과·저장된 적재 데이터를 변경하지 않습니다. 모델 준비 시간과 성능 측정은 독립 렌더링 점검 페이지에서만 표시합니다.

Three.js 일반 3D 화면에도 **무게중심점**을 기본 표시합니다. 상자와 팔레트 바닥판 자중을 포함한 좌표이며 표시 버튼으로 켜고 끌 수 있습니다. 관성 재생 중에는 현재 프레임의 위치에 따라 표시점이 움직입니다.

관성 계산이 끝나면 첫 프레임에서 대기합니다. **재생**을 눌러 움직임을 확인하세요. 테스트를 종료하거나 입력을 바꾸면 원래 적재 모습으로 돌아갑니다. 관성 재생은 저장된 배치 좌표를 변경하지 않습니다.

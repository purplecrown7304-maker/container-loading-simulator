# 개발·검증·배포 운영 규칙

## 1. 운영 원칙
2026-10-06 대표 지시에 따라 GitHub Claude 자동 검수 워크플로와 AI 간 의무 교대 검수를 제거합니다. 특정 AI의 검수는 병합이나 배포의 필수 조건이 아닙니다.

## 2. 작업 흐름
1. 대표의 요청과 AGENTS.md를 확인하고 변경 범위를 정합니다.
2. 작업 브랜치에서 구현하고 필요한 회귀 테스트를 추가합니다. main 직접 커밋은 금지합니다.
3. PR에 변경 내용, 검증 결과, 남은 위험을 기록합니다.
4. 변경에 적용되는 타입·테스트·아키텍처·보안·빌드 검사와 기존 GitHub CI 및 Vercel 검증을 수행합니다.
5. 대표 승인 후 정상 PR 병합과 배포를 진행합니다. 대표의 명시적 배포 지시는 검사 통과 후 정상 병합을 포함합니다.
6. 실제 운영 배포 상태와 운영 주소 반영을 확인한 뒤 완료를 보고합니다.

## 3. 독립 검토
대표가 요청하거나 작업에 도움이 될 때 별도 검토를 수행할 수 있습니다. 특정 도구나 AI를 의무 호출하지 않습니다. 검토 시 하드 안전 제약, 결정론, 회귀 테스트, 모드 분리, UI·엔진 분리를 확인하고 구체적인 지적을 기록합니다.

## 4. 유지할 규칙
- 하드 물리 제약과 AGENTS.md의 엔진 규칙을 유지합니다.
- 기존 GitHub CI, 보안 검사와 Vercel 배포 검증을 유지합니다.
- 검증 실패를 숨기거나 보호 설정을 우회하지 않습니다.
- 루트 보고서나 배포 트리거 파일을 만들지 않습니다. PR에 작업 결과를 기록하고 릴리스 요약은 CHANGELOG.md를 사용합니다.

# 기존 모델 Three.js 비교판 (로컬)

> 2026-10-02 후속 요청: Three.js만 사용합니다. Unity 런타임·프로젝트와 엔진 선택 UI는 제거되었으며 `?renderer=unity` 같은 과거 주소도 Three.js를 엽니다. 원본 8종 Meshy OBJ·MTL·JPEG는 바이트 변경 없이 `src/assets/Meshy`로 이동했습니다. `comparison.html`은 Three.js 렌더링 점검용 샘플 화면으로 유지하며, 배경은 공통 선택기로 변경합니다. 아래는 최초 비교판(PR #108)의 과거 검증 기록입니다.

기준: `bb3e337d64765286fdab00109fbf3fce0efa3610` (`main`, 2026-10-01 확인)

## 범위

- Unity가 기본 렌더러로 유지됩니다. Unity C# / WebGL 런타임 / 적재·Rapier·인증 엔진은 수정하지 않았습니다.
- `?renderer=three`로 연 세션에서만 Three.js가 켜집니다. `?renderer=compare`는 Unity부터 비교합니다. 각 뷰어 상단 버튼으로 동일 결과를 오가며 비교합니다.
- 입력/계산/인증/저장 데이터를 바꾸지 않습니다. 렌더러 선택은 URL에만 반영하고 저장하지 않습니다.
- PR #107의 `AGENTS.md`, `palletPacking.ts`, `palletTopLayerPolicy.test.ts`, `palletTopLayer.spec.ts`는 수정하지 않았습니다. 이 비교판에는 아직 병합되지 않은 PR #107 로직도 포함하지 않습니다.

## 실행

저장소에서 기존 잠금 파일대로 의존성을 설치한 뒤:

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm preview --host 127.0.0.1 --port 4173
```

- 독립 비교 화면: `http://127.0.0.1:4173/comparison.html?renderer=three`
- 실제 작업 UI 비교: `http://127.0.0.1:4173/?renderer=three`
- 일반 작업 UI: `http://127.0.0.1:4173/`

독립 비교 화면은 회사 데이터 저장소에 접속하지 않습니다. 목재·플라스틱 팔레트, 박스 12개, 박스 1200개, 빈 장비 샘플을 두 렌더러에 동일하게 전달합니다. 트럭, 장비 형상, 합성 자세 재생도 전환할 수 있습니다. 샘플 배치는 렌더링 검사용이며 엔진 계산이나 물리 안전 인증의 근거가 아닙니다.

## 원본 모델 유지

`unity/Assets/Resources/Meshy`의 다음 8종 OBJ / MTL / basecolor.jpg를 Vite URL로 직접 참조합니다. 모델 파일을 복사하거나 간소화하지 않았습니다.

- carton
- wood-pallet / plastic-pallet
- container-shell / truck-cab
- corner-guard / dunnage-block / dunnage-airbag

원본에 이미 적용된 회전은 재적용하지 않습니다. Unity OBJ 좌표계의 X 반사와 삼각형 앞면 방향을 보존하고, 모델 전체 경계만 단위 크기로 정규화합니다. 모든 원본 삼각형과 UV 연결, 텍스처 SHA-256을 테스트합니다. 현행 Unity의 흰색 혼합 틴트, 두 방향 조명 및 컨테이너 내부 clipping 셰이더를 재현합니다.

에어백 모델은 로더에 유지됩니다. 현재 공유 `securingGeometry`는 Unity에서도 에어백 장식을 생성하지 않으므로, 이 비교 작업에서 새 물리/보강 의미를 추가하지 않았습니다.

## 연결된 기능

- 박스 직접적재, 팔레트·혼합 적재, 팔레트 상세, 포장 미리보기, 장비 미리보기, 관성 재생, 팔레트 무게분포
- 동일 `unityPlan` 결과: 좌표/치수/회전 메타데이터/검증 경고/모델 종류/라벨/결속재
- 입체·상단·문쪽·측면, 궤도 회전/확대/이동, 장비 외벽 표시
- 박스별 네 면 라벨, 화물 선택 및 전역 선택 이벤트, 팔레트 선택, 바닥 하중 셀 및 CG
- 높이 단면과 적재 순서 재생: Unity처럼 하단 높이가 기준 이상인 상자를 숨기며, 메시를 절단하지 않습니다
- Rapier 위치·쿼터니언 재생과 팔레트에 부착된 결속재 이동
- 원본 메시/텍스처 요청 캐시와 공유, 색별 박스 인스턴싱, 정지 화면 demand rendering
- 리소스 로드 실패 시 오류를 노출하며, 원본을 원시 상자로 조용히 대체하지 않습니다

## 확인해야 할 차이와 제한

- GPU 셰이더 컴파일, 실제 화면·클릭·모바일 배치 및 전체 작업 UI 회귀는 브라우저 실행 검증이 필요합니다. 타입/단위 테스트 성공만으로 시각적 동등성을 확정하지 않습니다.
- dot 클라우드 브라우저에서 로컬 미리보기 접근이 `net::ERR_BLOCKED_BY_CLIENT`로 차단됐습니다. 우회하거나 공개 배포하지 않았습니다.
- Three.js 뷰어의 5초 회전 버튼은 해당 렌더 루프만 측정합니다. Unity 대비 속도 향상이나 적재 계산 성능을 뜻하지 않습니다. 아직 실측 FPS/초기 로딩 비교 수치는 없습니다.
- 모델 준비 시간은 컴포넌트 준비 이후의 모델·라벨·첫 렌더까지로 측정합니다. 초기 JS 로딩, 네트워크/캐시 상태, 화면 해상도는 별도로 기록해야 합니다.
- Unity와 Three.js는 서로 다른 AA/픽셀 비율/드라이버 경로를 사용하므로 완전한 픽셀 일치를 보장하지 않습니다.
- 현재 프레임 타입은 원래 계획 ID를 포함하지 않습니다. 부분·비정상·이전에 다른 계획에 연결된 프레임 객체는 거부하지만, 새 객체로 온 동일 개수의 오래된 프레임은 공통 엔진 타입을 바꾸지 않고 식별할 수 없습니다. 기존 관성 도구의 최신 타깃 전달을 사용합니다.
- 렌더러 전환은 카메라/선택 등 화면 상태를 초기화합니다. 적재 결과는 유지됩니다.
